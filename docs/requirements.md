# Requirements and evidence

As of 28 Nov 2026. This page maps each requirement Aksha was built to, paraphrased, to how the code meets it and where to check. Each evidence item is a file path, a pytest node ID or a command with its expected output. The same rows are in [requirements.json](requirements.json) for tools and agent reviewers, and [`tests/architecture/test_requirements_evidence.py`](../tests/architecture/test_requirements_evidence.py) fails if any path or test named there stops existing.

Of 97 rows, 89 are met, 7 are partly met and 1 is not met. Every row that is not fully met says why. The numbers quoted come from fake model mode, so they test the harness and the offline rules, not a model.

To run one row's tests, pass its node IDs to pytest, for example `.venv/bin/pytest -p no:xdist tests/integration/test_router.py::test_route_abstains_and_asks`.

## Rows not fully met

- **R-20** (partly met): The bundled worlds hold no page describing a manual alternative, so only the not-found path is tested.
- **R-33** (partly met): The matrix equals the key on the bundled worlds, but the offline comparison counts words, so some held-out worlds get wrong cells (limitations item 19); a live model is the fix.
- **R-36** (not met): No patent Task reads a `research.*` artifact, so no recommendation cites research work; the two agents share only the uploaded inputs.
- **R-47** (partly met): The design is written down, but it cannot be shown to have come before the code.
- **R-55** (partly met): Saving with IDs and versions is met; the patent agent reading them is not (see the patent agent row on research outputs).
- **R-64** (partly met): On the held-out worlds the research agent passes 25 of 26 cases and the patent agent 17 of 24 in fake model mode (limitations item 19).
- **R-83** (partly met): The outside contributor is already in the base inputs; the change re-dates the email so the contribution predates the agreement, rather than adding a person the first run never saw.
- **R-84** (partly met): In the demo the restart comes after the rebuild, during the send; a restart between the change and the rebuild is covered by tests, not shown in the demo.
