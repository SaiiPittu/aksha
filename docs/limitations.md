# Known limitations and what comes next

As of 27 Nov 2026:

1. **One local sandbox backend, Linux only, and one optional cloud backend.** Bubblewrap (strength `os-jail`) is the only local confining backend (P12); a container backend, the materialisation cache and nested tree manifests are designed and not built. A host without bubblewrap, or with unprivileged user namespaces turned off, runs no exec tool unless `AKSHA_SANDBOX=e2b` sends it to E2B (strength `vm`), which needs `E2B_API_KEY` and has been tested against a stubbed service only, never the live one. On E2B a policy's writable and protected paths decide only what is collected, not what a program may write inside its own VM, and an environment image (`/env`) is refused. The box's total memory and writable storage are sampled every 20 ms and the box is killed on a breach, so a box can overshoot by one interval's growth; no cgroup limit is built. Neither example agent has an exec tool yet. A first image build that no policy pre-approves needs an operator grant (`AKSHA_APPROVED_ENVIRONMENTS`); the approval interrupt for it is not built.
2. **A session's sandbox is stateful, and a crash can lose what was only in it** (decision 37, accepted risk). Every exec of a session's runs uses one workspace: a folder under the data directory bound as `/work` (bubblewrap) or one remote sandbox kept by its ID (E2B). It is kept after the run and removed by `aksha sandbox clean <session>`; removing it when a session is erased waits for erasure (item 9). What a program left only in the box's temporary space (`/tmp`, or a paused E2B sandbox that expired) is lost on a crash, a reboot or a kill. Files in the session folder survive; a git workspace (`AKSHA_WORKSPACE` naming a repository) is checkpointed as a commit on `aksha/<owner>/<session>` after each exec that changed it, and the program cannot run git itself because the repository's git folder is not in the box. Per-exec tree versions in the event store (ADR-P12 D5), which would make a crash lose nothing, are designed and not built, so an exec's workspace is not part of the record a replay rebuilds from: the record names the folder or sandbox and the outputs' hashes, not the workspace's content.
3. **The only system of record is a mock.** An approved send from the command line goes to the development mailbox `AKSHA_SYSTEMS` binds (a JSON file); no real mail or document system is built. Without the setting the approval is refused `system_unavailable` and the run keeps waiting. A run that was approved by a process with the mailbox and resumed by one without it waits too, and says why, while the owner's other runs go on; recovery still refuses an owner with an unfinished send and no system for it.
4. **OTLP/HTTP export is not built.** Traces go to local OTLP JSON Lines files only; sending them to a collector over HTTP is designed (P21) and not built.
5. **Steering reaches a run only between turns.** A steer is read before the next model call, never inside one, a resumed re-entry's earlier session does not show the inputs it consumed, and a summary that folds in a turn which read a steer is built from the turns alone, so the steer's text drops out of later contexts (its facts stay in the log). An amendment corrects only an instance's single-question `input` interrupt through `Steer`; a several-question one needs `AnswerInterrupt(amend=True)` with an answer per question.
6. **A rebuilt Task starts from a fresh context.** When invalidation rebuilds work, the rebuilt instance starts from a fresh context that opens with what changed (`rebuild_brief`); that is the default. Resuming the instance in its own recorded history, with stale tool results masked and a change notice, is built (decision 36) but off by default: a run opts in with `AKSHA_REENTRY=resume`, and a resume that hits a named trigger (a moved premise, a blocked or looping session, injected text, a changed definition, a session over budget) falls back to fresh. Resume becomes the default only if the measured comparison of the two shows it does better. The comparison runs (`aksha eval run change`), but only in fake model mode, where it shows that the arms run and grade correctly and not which mode is better; the live-model run that decides has not been done.
7. **Egress is per tool, not per process.** The runtime's HTTP client enforces each tool's policy, and the source scan refuses network imports in agent and extension modules; a body that hides an import (`getattr` chains, `exec`) is beyond the scan, which is why only trusted folders load.
8. **Anchoring is partial.** A file anchor sink and `verify_against` exist; scheduled anchoring, a `chain.anchored` event and a write-once sink do not.
9. **Erasure is open.** An append-only, hash-chained store and erasing personal data pull in opposite directions; P30 lists options and picks none. Memory's `forget` therefore hides a record from recall and erases nothing: the text stays in the record's earlier versions, in the recall results that showed it and in the model steps that read them. `erasure_inventory` lists every one of those places, for whichever option P30 takes.
10. **One Task instance at a time.** Concurrency above one is refused by the loader, and so is a keyed Task below another keyed Task. Since the supervisor slice (ADR-P15 S5, Proposed) a keyed worker may sit below an un-keyed supervisor, so the patent agent's per-candidate workers run one after another under it. The supervisor's admission is model-written inside code bounds, and its audit of the drops checks only a sample: a wrong drop outside the sample is not caught, which is why the miss rate is reported rather than claimed. The scale path (instructions to the board, criteria changes, an incremental board, pivot ranking) is not built.
11. **Live mode is wired and smoke-tested, but no agent has completed a task on a real model.** `AKSHA_MODE=live` binds every alias (generation, and decide and extract in adapted mode) to LiteLLM by default (`aksha-harness[live]`, ADR-P07 G6), or to the standard-library chat-completions adapter. On 27 Nov 2026 the LiteLLM adapters were smoke-tested by hand against `gemini/gemini-4-neon`: a forced tool call and the follow-up turn that answers it (the thought signature LiteLLM keeps in the call ID was accepted), one decide call and one extract call, each contract held (the extract quotes were found verbatim and the unstated field was left null). The API answered slowly and often with 503 (high demand), and one decide attempt timed out at the 90-second fast-class default; generation took 55 to 75 seconds a call and extraction 128 seconds with the timeout raised. A read tool's own step timeout (120 seconds for the research agent's reads) still bounds the fast calls its body makes, so a slow thinking model can time a read out whatever `AKSHA_LIVE_TIMEOUT_S` says. LiteLLM's bundled price map (release 1.111.0) has no price for `gemini-4-neon`, so its calls record cost 0 and a money budget does not bind on it; tokens are real. Nothing is known yet about how well a real model decides kinds, fills schemas or follows the Task prompts across a whole run. No built-in native System 1 adapter ships: a native extraction or classification service is named with `AKSHA_ALIAS_<ALIAS>`. Every threshold is unfitted. Native file input is off by default; with `AKSHA_NATIVE_FILES=on` intake records the `native_file` route and the adapter can send a file part, but nothing in the loop attaches a document's bytes to a model request yet, so the agents still read the text representation. The LiteLLM pin is two days old at the time of writing; it was chosen because it fixes every listed advisory, and LiteLLM's advisories mostly concern its proxy server, which Aksha does not use.
12. **Evals run in fake model mode only, and the coding agent has never run.** The research and patent agents run their suites on the runtime with rule-based fakes, so the numbers are plumbing checks; live mode is not run, and a recorded live run replays (`aksha replay`) but none has been recorded yet. The rule of three is a reading for the third agent, not a run.
13. **The agents' offline models read a grammar, not free text.** With no live model, the research agent's fake finds the dimensions and review themes in a small request grammar (`Compare ...`, `say about: ...`) and the patent agent's fake compares prior art by one element per mechanism step and its distinctive words; neither is a model, and a request outside the grammar compares on price only and reads no themes. The offline fast-class fakes decide kinds and fill schemas with general rules over what each request carries, and pass three worlds of different shapes (`stillroom`, `tilldew`, `cindral`) and, for research, three held-out worlds written without sight of them (item 19), but they are rules, not models. The patent fake still carries a hand-written lexicon for the stillroom notes (`fakes_stillroom.py`), used only when a note's ID and title are exactly those.
14. **Inputs are converted to text, kept per user.** Every upload goes through the ingest extension (ADR-P31, draft): PDF, Word, PowerPoint, Excel, email, HTML, Markdown, JSON, CSV and images are typed from their bytes and reach the agent as a header that says what was done, then their text, with each email attachment as its own input. The parsers are the extra `aksha-harness[ingest]`; without it those types are named gaps. Every parser runs in a worker process, never in the runtime's: a wall-clock, CPU and memory cap (`Caps.parser_time_ms`, `parser_cpu_s`, `parser_memory_bytes`), no network (its own network namespace where the kernel allows unprivileged ones, and TCP blocked by Landlock ABI 4 or later), no file writes (Landlock ABI 3 or later) and no new processes, and inside a bubblewrap box with read-only access to the one input file when `AKSHA_SANDBOX` names bubblewrap. A parser that hits a limit or dies leaves the document a named gap (`parser_timeout`, `parser_memory`, `parser_crashed`) and the upload goes on. A worker that cannot be contained (no Landlock ABI 3 and no bubblewrap box, or a runtime run as root without bubblewrap) is refused: every document is the gap `parser_uncontained` and no parser runs. Without bubblewrap, each upload pays a worker start once per pool; with it, about a second per document, since a box holds one input. Scanned PDF pages are dropped and named (no OCR rung is built), images are not described (no vision rung is built), HEIC needs pillow-heif installed separately (its wheels are GPL-2.0), and an image reaches the model only as its header until the agent loop sends native image blocks; legacy `.doc`, `.xls`, `.ppt` and `.msg`, audio and video are named gaps. Each user's inputs are one workspace that all their sessions read (`<AKSHA_HOME>/inputs/<user>/`); uploading a single file stores it under its name, so to replace a file inside an uploaded folder upload the folder again. An upload adds or replaces files and removes only an email's old attachments when the email is uploaded again: a file deleted from the folder stays among the inputs until `<AKSHA_HOME>/inputs/<user>/` is cleared. What a file holds comes from the decide and extract models; offline, from their rule-based fakes, so a layout their rules do not cover is decided `other` and left to the general model, which offline is the rule-based policy too.
15. **Some reopening is wider than the change.** A changed seller page re-resolves the companies, which reopens every company's evidence (it reads the whole competitor list) though each saves an equal profile; a changed row of a table reopens what read that row, and a renamed name inside it moves it too.
16. **The patent agent reads people and disclosures from tables, and dated prose only for disclosures.** A contributor's role or an agreement stated in prose ("the two welders are outside contractors with no IP agreement") reaches no contributor view: the record is listed `unread` for the general model to read with `read_document`, but no tool attaches what it says to a candidate. A disclosure written as prose is read one dated block at a time, its audience left `unknown` for counsel. A record holding several kinds is decided section by section (ADR-P07 G4), but an edit to one section reopens all the work built on that record.
17. **The web is offline unless a live provider is set, and live search is tested only against a stub.** `AKSHA_SEARCH=world` serves a world's small offline web: its pages and its noise are declared in `web.json`, ranked by shared words for any query, the same way every time. It is a stand-in for a search engine, not one: no query rewriting, no freshness and no pagination, and the offline models are told the searches a person would make in that market (`web.json`'s `fake` hints). `AKSHA_SEARCH=brave` calls the Brave Search API with a key from the environment and fetches each page over HTTPS under the `aksha.web` egress policy; it has been tested only against a stub server on localhost, never the live API. A fetched text page is read as text and a fetched PDF or Office file through document ingestion (ADR-P31); a world's offline web holds text pages only, and a page's links are not followed unless a search returns them. The search provider's own host is called by the adapter directly, outside a tool's egress policy (the pages it names are fetched under it). Only the research agent's vendor pages and, in two worlds, the patent agent's publications are on a world's web; a world's change sets move uploads only, so a web page that changes reaches no rebuild.
18. **A replay answers only what was recorded.** `aksha replay` answers each model call from the recording by its step (a generation) or by its request hash (a fast-class call), each search by its query and limit and each fetch by its URL, in the order the run asked them; any call the recorded run did not make is refused (`replay_missing`, `replay_mismatch`), never answered. A replay therefore needs the same agent definition, the same inputs and the same answers; a change to an agent's prompt or tools makes its recordings stale. A replay's clock is fixed at the recorded start, so a run that spanned days replays on its first day. Only the scripted person's answers by question ID and blanket approvals can be recorded (`--answer`, `--approve`); a choice answered in another way, a steer or an upload in the middle of a run is not. No live recording exists yet: the shipped one was made from a fake run.
19. **Known generality gaps of the offline fakes, found by the held-out worlds.** Six worlds were written without sight of the agent code (`rimefold`, `kelasora`, `vantlow` for research; `pulvane`, `quillmere`, `brackwen` for patent). As of 27 Nov 2026 the research fakes pass 25 of their 26 cases and the patent fakes 17 of their 24 (they passed 3 of 23 before the reader and the graders were made general; `pulvane` gained a case for its parameter-conflict trap), while the first three worlds still pass every case. Each gap below is left failing rather than fixed with a rule that fits one world.

    | World | Patent cases before | After | What still fails |
    |---|---|---|---|
    | `stillroom`, `stillroom-v2` | 8 of 8 | 8 of 8 | |
    | `tilldew` | 6 of 6 | 6 of 6 | |
    | `cindral` | 5 of 5 | 5 of 5 | |
    | `pulvane` | 1 of 7 | 7 of 8 | the happy case's matrix and one next action |
    | `quillmere` | 0 of 7 | 3 of 7 | the happy case and both combination traps (matrix, next actions), the units trap |
    | `brackwen` | 2 of 9 | 7 of 9 | the happy and partial-disclosure cases (matrix) |

    - Research, `rf-research-claim` (`rimefold`): a vendor's unqualified accuracy figure ("Accurate to ±0.1 °C across the full range") sits inside a hard-wrapped datasheet block. The page reader marks claims only by marketing words ("up to", "best-in-class") and cites whole blocks, so the claim is shown and labelled but its citation is the block, not the sentence (`citation.overlaps_key`).
    - Patent, the comparison (every remaining patent failure but one): what a matrix cell holds is a judgement of whether a family's text shows a step, and the offline model makes it by counting the step's first six distinctive words in the family's text (all: `disclosed`, at least half: `partial`). A paraphrase ("discards a window when motion exceeds a limit" for "accept a 30-second window only when motion stays below 0.05 g RMS") reads `partial` where the worlds' authors read `disclosed`, and a family that shares a step's words without its mechanism reads `partial` where they read `not_found`. In the held-out worlds 17 to 25 of their 67 keyed cells differ under any word-count threshold tried, so no threshold fixes it; the next actions are rules over the matrix (`rules.next_action`) and inherit the difference, and so do the two combination traps (`T-OBVIOUS-4`, `T-OBVIOUS-5`), which read the matrix element by element. A live comparison model is the fix.
    - Patent, `T-UNITS` (`quillmere`): a collaborator's poster states the key step's threshold in other units (0.004 m3/m3 per hour for the notebook's 0.4 % VWC per hour). The poster is found and cited as the write-up of its register row, but the offline model compares words, not quantities converted between units, so it does not read the poster as showing that step.
    - What was fixed, by structure and in general: the ingestion layer reads WebVTT and plain-text call transcripts (speaker turns), XML, JSON Lines and YAML (ADR-P13 G5); the patent reader cuts a record into units (a notebook's pages, a tracker's entries, a search export's hits) and reads each by the decide-then-extract path, names a candidate by the identifier the other inputs use, keeps a document's own step labels and a later step's own date, reads a register as a table whatever its format, joins a write-up to the row it dates, and groups a family by its priority numbers wherever they sit (ADR-P07 G5); the graders and the self-test oracle read field names and expectations from each world's key, and seven traps have checks (ADR-P22 G7). These three worlds were read while the reader was made general, so they are no longer held out: the numbers above say the rules cover their shapes, not that the rules generalise to a world nobody has read, and a fresh held-out world is the next measure. To keep the rules from naming what was read, `tests/architecture/test_no_world_leakage.py` now also scans the offline models (every `fakes*.py` but the stillroom lexicon) for any world's names, identifiers, file names and field names, and a bibliographic key is read by the words it is made of rather than from a list of export spellings. The scripted user's answer to a note's open detail is still keyed by world in `evals/agents/patent.py` (`GAP_ANSWERS`); it is the person's knowledge, not a grader, and the held-out worlds take its default.

20. **Corrections trust the role they are sent under.** A correction (`aksha correct`, ADR-P05 C1, Proposed) is decided only under the domain owner's role (`AKSHA_CORRECTION_APPROVER`), but nothing checks that the sender holds that role (`--by`); the other commands share this trust model. An agent proposes a correction through the session API under `agent:<name>`; no tool lets it propose one inside its own run. A correction routed through the outbox is delivered at least once, so a crash between delivery and receipt can deliver it later over a newer record in the shared system. A correction to a converted upload (a PDF's text) is written as given, without the ingester. Nothing tests directly that citations carry over to a corrected version.
21. **Cross-run reuse is keyed by writer.** A later run of the same agent reuses an earlier run's version when every read it recorded still holds (`artifact.reused`), and for a citation-keyed agent only its strong dependencies are checked. `AKSHA_REUSE=off` or `reuse="off"` on an agent makes every run recompute.
22. **The definition hash does not see a dynamic import by a computed name.** The agent definition hash pins the modules an agent imports, including `importlib.import_module` and `__import__` with a literal name, but an import whose name is computed at run time is invisible to it. The ingest extension's worker and model routing import this way, so a change to what they load does not change the hash.
23. **A failed rebuild can be re-entered by a later evaluation.** When a Task instance the rebuild plan lists fails (its stop-veto limit, its turn limit, a check that raised), the evaluation that failed it no longer re-enters it: the run goes on to other work or ends `blocked`, naming the instance ([#95](https://github.com/SaiiPittu/aksha/issues/95), ADR-P15 S6, Proposed). Before, it was re-entered within that evaluation until the loop bound refused the run (`StopRefused: evaluation_loop: ... did not settle`). A later evaluation of the same run does not remember the failure, so while other work runs the scheduler may re-enter the blocked instance once per evaluation, bounded by the run budget. No rule yet says whether a failed rebuild waits for a person or a new change before it is tried again.

## What comes next

The status of each roadmap item is in the [README](../README.md#roadmap).

[docs/design/05-future-directions.md](design/05-future-directions.md) records what an unattended software factory needs on top of the first release, each item an extension of an existing primitive: a stronger isolation tier for untrusted code (X-1), a halt-everything stop (X-2), repeated denials that ask a person (X-3), per-agent identity and credentials (X-4), an untrusted-origin mark that follows lineage (X-5), a conversation view and a cross-run approval inbox (X-6), and runs started by incoming events (X-7). X-1 to X-7 are designed and not built; X-8, the hash-chained event store, is built, with external anchoring next.

The nearer steps: a container backend behind the P12 port, a real system of record behind the outbox, OTLP/HTTP export, and a whole task on a real model, then the live-model run of the comparison of fresh and resumed rebuild contexts (it runs in fake model mode today), and a retry rule for a failed rebuild (item 23).
